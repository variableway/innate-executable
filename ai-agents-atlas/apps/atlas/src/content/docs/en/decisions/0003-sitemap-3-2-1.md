---
title: "ADR-0003: Pin @astrojs/sitemap to 3.2.1"
description: Why the sitemap integration stays on an old major.
date: 2026-08-01
status: accepted
---

## Context

`pnpm install` initially resolved `@astrojs/sitemap` to **3.7.3** (the
then-current latest). The build completed but crashed at the
`astro:build:done` hook with:

```
Cannot read properties of undefined (reading 'reduce')
  at astro:build:done
  .../@astrojs/sitemap@3.7.3/.../dist/index.js:85:37
```

## Investigation

Sitemap 3.7.x expects to be populated by the `astro:routes:resolved`
integration hook. That hook **was added in Astro 5**. On Astro 4.16,
the hook never fires, `_routes` stays `undefined`, and the first
`.reduce()` call throws.

## Decision

Pin `@astrojs/sitemap@3.2.1` in `package.json` (devDependency).

```json
"devDependencies": {
  "@astrojs/sitemap": "3.2.1"
}
```

3.2.1 is the last release before the `astro:routes:resolved`
dependency was added. It works against the v4.16 build pipeline and
generates an identical sitemap.

## Consequences

### Positive

- Build is reliable; no more `reduce`-on-undefined crashes.
- Sitemap output is unchanged from the newer version for our static,
  no-i18n site.

### Negative

- We can't pick up any 3.7.x or 3.x bug fixes that don't relate to the
  route hook.
- When we upgrade Astro to 5, we should re-evaluate and likely bump
  sitemap.

### Alternatives considered

- **Upgrade Astro to 5.** Blocked by the Content Collections loader
  rewrite; would require migrating every schema in `config.ts`.
- **Use a custom sitemap generator.** Rejected as over-engineering
  for a static site.
- **Disable sitemap.** Rejected — search engines and RSS readers
  benefit from it.
