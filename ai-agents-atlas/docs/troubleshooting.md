## "No valid renderer was found for `<file>`"

You're using a React component in an `.astro` file but `@astrojs/react`
isn't registered. Check `astro.config.mjs`:

```js
integrations: [react(), /* ... */]
```

## "Cannot find module 'zod/v3'" or "Package subpath './v3' is not defined"

Astro's content layer transitively pulls `zod-to-json-schema@3.25.x`,
which expects the `zod/v3` subpath. Pin it via
`pnpm-workspace.yaml`:

```yaml
overrides:
  zod-to-json-schema: 3.23.5
```

Note: `pnpm.overrides` in `package.json` is **not** read by pnpm 11+.

## "Could not parse `style` attribute on `span`"

`@mdx-js/rollup` incompatibility with `hast-util-to-estree` 3.1.3.
Pin in `pnpm-workspace.yaml`:

```yaml
overrides:
  hast-util-to-estree: 3.1.0
```

## "The collection 'useCases' does not exist or is empty"

Astro's legacy `type: 'content'` collections derive the collection name
from the **directory name**, not the export key. The directory must be
`useCases/` (camelCase), and the schema entry must be `useCases`.

If you need kebab-case for readability, switch to `defineCollection`
with a loader (`glob`/`file`) — but only the legacy path matches
Astro 4's content layer semantics out of the box. See
[decisions/0002-use-cases-camelcase.md](./decisions/0002-use-cases-camelcase.md).

## Sitemap crashes with "Cannot read properties of undefined (reading 'reduce')"

You're on `@astrojs/sitemap@3.7.x` with Astro 4. The 3.7 release depends
on the `astro:routes:resolved` hook, which only exists in Astro 5.
Pin to 3.2.1. See
[decisions/0003-sitemap-3-2-1.md](./decisions/0003-sitemap-3-2-1.md).

## "Rollup failed to resolve import '/pagefind/pagefind.js'"

The Pagefind bundle is generated by the `pagefind` CLI *after* the
Astro build. Vite tries to bundle it during build. Two fixes:

1. Add it to `vite.build.rollupOptions.external` (already done in
   `astro.config.mjs`):

   ```js
   build: { rollupOptions: { external: [/^\/pagefind\//] } }
   ```

2. Declare the module in `src/types/pagefind.d.ts` so `astro check`
   doesn't complain.

## Frontmatter validation fails with a list of files

`astro check` and `pnpm build` both validate. Run them locally and
read the precise path. Common causes:

- `framework: "langchain"` — not in enum, use `cross`.
- Date strings without quotes: `publishedAt: 2025-08-12` works;
  `publishedAt: 2025/08/12` does not.
- Typo in enum value: TypeScript catches this immediately.

## A code fence renders as JSX

`cpp`, `python`, etc. are fine, but `ts`/`tsx`/single-letter tags can
be interpreted as components. If a fence misbehaves, pick a different
tag (`cp` works for `cpp`) or escape angle-bracket URLs as
`[link](url)` rather than `<https://...>`.

## Pagefind index never loads

1. Run `pnpm preview:build` to generate the index locally.
2. Check that `dist/pagefind/pagefind.js` exists.
3. Confirm `scripts/pagefind-tag.mjs` was run by the `postbuild` hook.
4. Reload — the island only mounts when it sees the `data-pagefind`
   marker in the HTML.

## localStorage changes don't appear

`localStorage` is per-origin, per-browser profile. If you open the
deployed site on `atlas.example.com` but develop on
`http://localhost:4321`, they're different storages. The store key is
`ai-agents-atlas:v1` — clear it from devtools if you need a reset:

```js
localStorage.removeItem('ai-agents-atlas:v1');
```
